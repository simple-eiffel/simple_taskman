## Findings
1. PDH rate counters collected 1-20 ms apart: the array call fails now and then
   (measured 6-12 of 50; never an item with a bad status; 0 ms and >= 100 ms
   apart always succeed). The library already reports such a tick as
   "unavailable" - verified live: 39 with a value, 11 unavailable, 0 invalid.
   Test corrected to assert that honesty property, plus a value on every
   refresh at the worker's fastest pace (250 ms, 10 of 10). Oracle gotcha
   "PDH rate counters fail when collected too close".
2. TM_PATHS.is_plain_name: CHARACTER_32.is_alpha_numeric rejects Hebrew; the
   test's expectation was wrong. The rule is now explicitly ASCII-only (code
   check added, comment corrected): log file names stay portable.
3. Design note for the GUI and diagnosis phases (no defect): cpu.busy_pct uses
   "% Processor Time", which typeperf confirms swings 0.1-3.3% at idle while
   "% Processor Utility" holds ~2.2-2.4%. Task Manager on Windows 10+ bases its
   CPU figure on Processor Utility; decide which one the headline tile and the
   CPU saturation rule use before Phase 3.
